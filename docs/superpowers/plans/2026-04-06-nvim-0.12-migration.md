# Neovim 0.12 Migration Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix config incompatibilities and rendering bugs caused by upgrading to Neovim 0.12.

**Architecture:** Neovim 0.12 auto-starts treesitter highlighting in ftplugins for `lua`, `markdown`, `help`, and `query` filetypes. The current config's wildcard `vim.treesitter.start()` autocmd causes double-start for these types. Additionally, 0.12's markdown ftplugin maps `[[`/`]]` for heading navigation, conflicting with lsp-document-highlight.nvim. Several other deprecations and redundancies need cleanup.

**Verified 0.12 runtime behavior:** Checked `/opt/homebrew/Cellar/neovim/0.12.0/share/nvim/runtime/ftplugin/` — Neovim 0.12 calls `vim.treesitter.start()` in ftplugins for: `lua` (+ sets foldexpr), `markdown` (+ `[[`/`]]`/`gO` keymaps), `help`, `query`.

### Task 1: Fix TreeSitter double-start

The wildcard `FileType *` autocmd calls `vim.treesitter.start()` for every filetype. Neovim 0.12 already does this for lua, markdown, help, and query via ftplugins. For all other filetypes that have installed parsers, `vim.treesitter.start()` is still needed.

**Files:**
- Modify: `nvim/lua/plugins/nvim-treesitter.lua`

- [ ] **Step 1: Replace wildcard autocmd with filtered one**

Replace the entire `config` function in `nvim/lua/plugins/nvim-treesitter.lua` with:

```lua
return {
  'nvim-treesitter/nvim-treesitter',
  lazy = false,
  build = ':TSUpdate',
  config = function()
    -- Neovim 0.12 auto-starts treesitter for: lua, markdown, help, query
    -- Start it for all OTHER filetypes that have a parser installed
    local builtin_ts_fts = { lua = true, markdown = true, help = true, query = true }

    vim.api.nvim_create_autocmd('FileType', {
      pattern = '*',
      callback = function(args)
        if builtin_ts_fts[args.match] then
          return
        end
        pcall(vim.treesitter.start, args.buf)
      end,
    })

    -- Enable treesitter-based indentation
    vim.api.nvim_create_autocmd('FileType', {
      pattern = {
        'javascript',
        'typescript',
        'typescriptreact',
        'javascriptreact',
        'html',
        'css',
        'json',
        'lua',
        'bash',
        'php',
        'svelte',
        'pug',
      },
      callback = function()
        vim.bo.indentexpr = "v:lua.require'nvim-treesitter'.indentexpr()"
      end,
    })
  end,
}
```

- [ ] **Step 2: Verify no double-start**

Open a Lua file and a Markdown file, run in each:
```
:lua print(vim.inspect(vim.treesitter.get_parser():lang()))
```
Should print the language once. No visual glitches or flickering.

- [ ] **Step 3: Verify non-builtin filetypes still get highlighting**

Open a `.ts` or `.js` file. Verify syntax highlighting works. Run:
```
:lua print(vim.treesitter.get_parser() ~= nil)
```
Should print `true`.

- [ ] **Step 4: Commit**

```bash
git add nvim/lua/plugins/nvim-treesitter.lua
git commit -m "fix(nvim): skip treesitter start for filetypes handled by 0.12 ftplugins"
```

### Task 2: Fix `[[`/`]]` keymap conflict

Neovim 0.12's `ftplugin/markdown.lua` maps `[[`/`]]` (buffer-local) for heading navigation. The `lsp-document-highlight.nvim` plugin maps them globally for LSP reference jumping. The buffer-local ftplugin maps will win in markdown files, breaking the reference navigation. In non-markdown files, the global maps work fine.

This is actually desirable behavior — heading navigation in markdown, reference navigation elsewhere. But it needs a conscious decision.

**Files:**
- Modify: `nvim/lua/plugins/lsp-document-highlight.lua`

- [ ] **Step 1: Scope the keymaps to non-markdown buffers**

The current behavior is actually correct: buffer-local (ftplugin) maps override global maps. But `lsp-document-highlight.nvim` sets `lazy = false` with global `keys`, meaning lazy.nvim will load it on `[[`/`]]` press even in markdown — potentially interfering.

Change to use `config` instead of `keys` so the plugin loads immediately without lazy key interception:

```lua
return {
  'akioweh/lsp-document-highlight.nvim',
  event = 'LspAttach',
  config = function()
    vim.keymap.set('n', '[[', function()
      require('lsp-document-highlight').jump(-vim.v.count1, true)
    end, { desc = 'Previous Reference' })
    vim.keymap.set('n', ']]', function()
      require('lsp-document-highlight').jump(vim.v.count1, true)
    end, { desc = 'Next Reference' })
  end,
}
```

This way:
- Plugin loads on `LspAttach` (when it's actually useful)
- Global `[[`/`]]` maps are set for LSP reference jumping
- In markdown buffers, 0.12 ftplugin's buffer-local `[[`/`]]` maps take precedence (heading navigation)
- In code buffers, the global LSP maps work as before

- [ ] **Step 2: Verify in markdown**

Open a markdown file, press `]]`. Should jump to next heading (0.12 behavior), not LSP references.

- [ ] **Step 3: Verify in code**

Open a `.ts` or `.lua` file, place cursor on a symbol, press `]]`. Should jump to next LSP reference.

- [ ] **Step 4: Commit**

```bash
git add nvim/lua/plugins/lsp-document-highlight.lua
git commit -m "fix(nvim): load lsp-document-highlight on LspAttach, avoid markdown keymap conflict"
```

### Task 3: Remove redundant Comment.nvim

Neovim has built-in `gc`/`gcc` commenting since 0.10 (via `vim.keymap.set` in the runtime). Comment.nvim duplicates this. Removing it reduces plugin count and avoids potential conflicts.

**Files:**
- Delete: `nvim/lua/plugins/comment.lua`

- [ ] **Step 1: Delete the plugin file**

```bash
rm nvim/lua/plugins/comment.lua
```

- [ ] **Step 2: Verify built-in commenting works**

Open any code file. Press `gcc` to toggle a line comment. Press `gc` in visual mode to toggle block comment. Should work via Neovim's built-in support.

- [ ] **Step 3: Clean up lazy-lock**

In Neovim, run `:Lazy` and confirm Comment.nvim is no longer listed. If it's still in lazy-lock.json, run `:Lazy clean` to remove it.

- [ ] **Step 4: Commit**

```bash
git add nvim/lua/plugins/comment.lua nvim/lazy-lock.json
git commit -m "refactor(nvim): remove Comment.nvim, use built-in gc/gcc commenting"
```

### Task 5: Disable unwanted Lua foldexpr (optional)

Neovim 0.12's `ftplugin/lua.lua` sets `foldexpr = 'v:lua.vim.treesitter.foldexpr()'` for Lua files. If you don't use folding, this is harmless but may show fold columns or collapse code unexpectedly.

**Files:**
- Modify: `nvim/lua/autocommands.lua`

- [ ] **Step 1: Check if folding is visible**

Open a Lua file. If you see fold markers or collapsed code, proceed. If everything looks normal, skip this task.

- [ ] **Step 2: Add an after-ftplugin autocmd to reset foldexpr**

Add to the end of `nvim/lua/autocommands.lua`:

```lua
-- Disable treesitter foldexpr set by 0.12 ftplugins
vim.api.nvim_create_autocmd('FileType', {
  desc = 'Disable treesitter folding from built-in ftplugins',
  group = vim.api.nvim_create_augroup('disable-ts-folds', { clear = true }),
  pattern = { 'lua', 'markdown' },
  callback = function()
    vim.wo[0][0].foldexpr = '0'
    vim.wo[0][0].foldmethod = 'manual'
  end,
})
```

- [ ] **Step 3: Verify**

Open a Lua file. No folds should appear. Run:
```
:set foldmethod?
```
Should show `foldmethod=manual`.

- [ ] **Step 4: Commit**

```bash
git add nvim/lua/autocommands.lua
git commit -m "fix(nvim): disable unwanted treesitter folds from 0.12 ftplugins"
```
